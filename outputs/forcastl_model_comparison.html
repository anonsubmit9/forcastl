Forensic Log-Triage: Model Comparison

How well do language models detect malicious activity in Windows event logs?

FORCAST-L benchmark · generated 2026-06-18 · scoring contract forcastl_scoring_20pt_v1 · all models scored against one frozen ground-truth snapshot

Each model reads raw Windows event-log records (EvtxECmd CSV) for a single forensic artifact and must decide malicious vs. benign and extract the supporting evidence. We measure three things that matter operationally: how many real attacks it catches (recall), how often it cries wolf on benign activity (false-positive rate), and how often it invents evidence that isn't in the log (hallucination). Lower is better for the last two.

Results — same 120 questions, every model

A comparison is only meaningful when every model is asked the same question on the same evidence. Each model here saw the identical prompt (simple_malicious_prompt_v1) on the same 120 artifacts (60 attack / 60 benign) with identical ground truth and scoring — only the model differs. Best detection rate is highlighted; false-positive and hallucination rates are shown without a "winner" because the lowest value usually reflects a model that simply flags less.

What the benchmark is

  • 328 real artifacts — genuine Windows event logs, no synthetic data.
  • Attacks span 11 MITRE ATT&CK tactics, 60 techniques; benign set is real baseline/admin activity shaped as near-misses.
  • Evidence scored across 6 fields (event IDs, processes, accounts, commands, network, registry) on a 20-point rubric.
  • Identical question for every model — one frozen prompt template, parameterized only by the artifact; nothing is tailored per model.
  • Deterministic: models run at temperature 0.

Extraction quality

  • Claude Opus 4.8: 95/118 files graded A (81%), mean score 18.0/20
  • GPT-5.5: 85/119 files graded A (71%), mean score 17.4/20
  • Qwen3.6-27B: 81/108 files graded A (75%), mean score 17.7/20

Grade A = ≥17/20. High recall with low hallucination means the evidence a model reports can be trusted, not just its verdict.

How to read this — and what it does not say

  • Single run per model. Temperature 0 makes each run deterministic, but these are not yet averaged across repeated runs; treat differences inside the overlapping 95% confidence intervals as ties.
  • Coverage differs in the full-corpus table. The local model was scored on the 120-file Standard slice, not all 328 — use the head-to-head table above for any apples-to-apples claim.
  • A "false positive" here is strict. The benign set is deliberately adversarial (admin actions that look attack-shaped), so double-digit FP rates are expected and do not indicate a broken model.
  • This is an independent capability comparison, not a vendor endorsement.
Corpus provenance: attack artifacts from the public mdecrevoisier/EVTX-to-MITRE-Attack dataset (CC0); benign baseline from NextronSystems/evtx-baseline (Apache-2.0); both converted to CSV with EvtxECmd. Recall/FP confidence intervals are 95% Wilson; errored-benign files are excluded from the FP denominator and an errored attack counts as a miss. Sample representativeness: on the full 328-file corpus, Claude Opus 4.8 95.4%, GPT-5.5 94.5% recall — consistent with the 120-file results above, indicating the shared set is representative for those models. The local model was evaluated on the 120-file set only.
